# trueodds — CLAUDE.md

## What this is

A small **decision model**, trained from scratch on public data to learn how Jev-style "System One"
models work. It takes a state, a question and a list of options, and returns a probability for
each option from a single forward pass, with no generated text.

The point that makes it worth building is that it **measures whether its probabilities are true**:
accuracy on the datasets it was trained on, accuracy on datasets it never saw (generalization),
and calibration, meaning outcomes it gives 0.8 should happen about 80% of the time.

Runs entirely on consumer hardware: RTX 5060 Ti 16 GB, 32 GB RAM, Ubuntu.

**Status: Phase 2 done (2026-09-24).** The data (spec 001), the harness with its baselines
(spec 002), the GPU measurements (`docs/SETUP.md`), the model, the training loop and a trained model
exist. `phase2-templates/best` meets every Phase 2 exit criterion (pooled test accuracy 0.761, ECE
0.008); runs are tracked in MLflow (D24). Decisions run to D26. Next: Phase 3 (calibration).

## How to work here

1. **Start from `docs/PLAN.md`.** Work on the current phase only. A phase is done when its exit
   criteria are met and measured, not when the code looks complete.
2. **Harness before training.** The metrics and the baselines exist before the first model is
   trained, so the first number the model produces already has something to be compared with.
   Exit criteria are checked by running the harness, not by reading training logs.
3. **Known answers first.** Each metric is tested on inputs whose answer is known (a perfectly
   calibrated fake model has ECE ≈ 0; a model that always answers "A" scores the majority baseline)
   before it scores a real model.
4. **Specs only where a contract is not obvious.** Write a spec at the start of the phase that needs
   it. See `specs/README.md`.
5. **Keep the docs true.** If a change contradicts `ARCHITECTURE.md` or a decision in
   `DECISIONS.md`, update that document in the same commit. Add a new dated decision instead of
   silently editing an old one.
6. **Use plan mode at the start of each phase** to turn the phase tasks into concrete steps.

## Rules

- **The test split and the held-out datasets are never used for any choice.** Checkpoint selection,
  temperature fitting and hyperparameter changes use the dev split only (D6). Numbers on test and
  held-out are read, never tuned against.
- **Never commit data or weights.** Downloaded and processed datasets live in `~/.trueodds/data/`,
  checkpoints in `~/.trueodds/runs/`, the MLflow store in `~/.trueodds/` too, all regenerated by
  scripts (D12). Results JSONs in
  `harness/results/` are committed.
- **VRAM budget:** training must stay under 15 GB peak. Measure it; do not assume it.
- **Python via uv only** (`uv sync`, `uv run ...`). No pip, no manual venvs.
- **Claude Code subagents go in `.claude/agents/`**, not `.claude/subagents/`.
- Repo content is in English.

## Commands

```bash
uv sync                                   # base package (torch included, D21) and dev tools
uv run pytest                             # unit tests, model tests on the CPU (GPU tests deselected)
uv run ruff check . && uv run ruff format --check .
uv run --extra gpu <cmd>                  # training and GPU tools (tensorboard, nvidia-ml-py)
uv run --extra tracking <cmd>             # MLflow tracking and registry (D24)

uv run python scripts/prepare_data.py     # download and convert every dataset to ~/.trueodds/data
uv run python -m harness.evaluate --baselines
uv run python -m harness.report harness/results/*-baselines.json
uv run --extra gpu python scripts/gpu_bench.py
uv run --extra gpu python -m trueodds.train configs/<run>.yaml          # checkpoints in ~/.trueodds/runs/
uv run --extra gpu python -m harness.evaluate --checkpoint ~/.trueodds/runs/<run>/best
uv run --extra tracking mlflow ui --backend-store-uri sqlite:///$HOME/.trueodds/mlflow.db
```

Details and measured results are in `docs/SETUP.md`.
